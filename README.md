# Умный калькулятор

Веб-приложение для базовых и расширенных математических операций с высокой точностью.
Бэкенд на Ruby + Sinatra, вычисления на `BigDecimal`, собственный разбор выражений (без `eval`).
Конкурсное задание «Умный калькулятор», второй тур Авторской мастерской «Атомный код: будущее уже сегодня».

## Требования

- Ruby **3.1 или новее** (проверка: `ruby -v`)
- Bundler (идёт вместе с Ruby; проверка: `bundle -v`)

## Установка зависимостей

```
cd smart_calc
bundle install
```

## Запуск

```
bundle exec ruby app.rb
```

Адрес приложения: **http://localhost:4567**

Остановить сервер: `Ctrl + C`.

## Запуск тестов

```
bundle exec ruby test/calc_logic_test.rb
bundle exec ruby test/app_test.rb
```

## Возможности

- Операции: `+  -  *  /  ^  %`, скобки, `sin cos tan cot` (углы в градусах), `ln`
- Точные дроби: `0.1 + 0.2 = 0.3`; периодические дроби округляются до 10 знаков и помечаются `≈`
- Деление на ноль и выход за область определения функций: понятное сообщение об ошибке
- Проценты: `200 + 10% = 220`, `200 * 10% = 20`
- Ограничение ввода числа — 16 символов; длинные результаты сворачиваются («Показать полностью»);
  числа больше 10^15 показываются в экспоненциальной записи (`1.23e+16`)
- Светлая и тёмная тема, адаптивный дизайн, ввод мышью и клавиатурой, история последних 10 вычислений

### Разбор случаев, когда ИИ ошибался

**Случай 1: Неверный тест для больших чисел.**

ИИ написал тест `test_number_length_limit`, который ожидал, что число `1234567890123456` будет показано в обычной записи. Однако по Положению числа больше 10^15 должны показываться в экспоненциальной записи. Калькулятор работал правильно, а тест был написан неверно.

**Исправление:** Claude предложил исправить тест одной командой, заменив `assert_result` на `assert_equal` с проверкой поля `:full`:
```ruby
ruby -e 'f="test/calc_logic_test.rb"; s=File.read(f); s.sub!("assert_result \x271234567890123456\x27, \x271234567890123456\x27", "assert_equal \x271234567890123456\x27, calc(\x271234567890123456\x27)[:full]"); File.write(f,s)'
